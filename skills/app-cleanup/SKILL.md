# 应用盘点与分类清理

## 1. 先确认读取范围，再开始调查

**在读取目标应用、浏览器、历史记录、凭据元数据、项目目录或进程信息之前，先向用户说明准备读取什么、读到什么粒度，以及不读取什么，并等待明确确认。** 加载本 skill 和其工具说明不算读取用户数据。此前审计结果是背景，不自动授权本次读取或清理；用户已明确确认且范围未变时不重复询问。

采用适合目标的最小范围，不要求用户先填技术问卷。例如：

> 我准备只读查看应用安装信息与相关配置/缓存目录、浏览器历史的标题与网址及站点存储元数据、凭据的名称/存在性；不读取密码、Cookie 值或会话/邮件正文，也不进行任何删除。是否同意？项目文件或会话数据库的进一步检查如有必要，会先说明新增读取范围。

这只是示例，不是默认授权清单。用户可缩小范围；被拒绝的分支不读。打开应用可能产生启动/最近使用记录，退出应用会改变运行状态，数据库只读连接也可能产生锁或共享内存文件：不要将它们描述为零副作用。不为盘点启动目标应用；确需打开浏览器/密码管理器或退出运行中的应用时，先说明并获得相应许可。系统密码由用户在原生界面输入，不发送到聊天。

## 2. 确认后只读梳理，交付分类清单

按已确认范围查询；关键词仅定位，不能直接成为删除依据。核实应用身份、路径实际存在性、符号链接、配置归属、浏览器配置文件和共享消费者。不要回显凭据值、登录链接令牌或不必要的私密正文。

依据实际发现分组，不套固定数量。常见类别：程序/启动入口；专属本地数据；旧备份；系统集成；凭据；浏览器历史/站点数据；终端痕迹；共享工具配置；工作会话；项目与个人资料。

清单按类别说明：发现和位置、实际核查范围、拟处理动作、保留项、恢复机制、影响及未检查范围。把“不存在”“权限受限”“未检查”分开；旧路径消失不代表永久删除或知道谁做了什么。混合备份、共享模型定义、实际会话、Git 工作副本不能当缓存一并删。具体技术检查见 [平台与应用边界](references/platform-notes.md)。

## 3. 逐类确认，处理一类再问下一类

- 每次确认一个有明确语义的类别，不是一个文件，也不是一揽子全选。先问该类，再执行与验证；用户指定其他节奏时遵循指定方式。
- 每次交代目标、删除/移入废纸篓/解除关联等动作、是否可恢复、登录/同步/运行影响。需要关闭应用时一并确认；永久删除不得借“清理”含糊带过。
- 用户明确的保留规则持续生效，例如所有书签、书签备份、标签组和组内条目。询问浏览器数据时再次明确不涉及这些对象，不反复索取已确认的保留决定。
- 用户跳过的类别记录为保留，不作为失败，不再试删。范围、共享契约、替代模型或影响改变时重新确认，只暂停依赖该决定的分支。
- 清理共享工具只处理明确归属的记录与关联，不卸载整套工具。会话按所有消息的模型元数据及实际父子/引用关系判断；混合关联组默认整体保留，除非另获明确拆分方案授权。

## 4. 执行前建立可验证的断言

先读 [验证契约](references/verification.md)，用本批分类清单制定 `manifest.json`，**同时覆盖清理目标和保留内容**。有破坏性操作而没有可执行验收时先补齐验证手段，不能先删再决定怎么证明。

复用 `scripts/verify_cleanup.py`：Python 3.9+，仅标准库，不依赖操作系统，不执行删除或外部命令。它直接检查文件系统、JSON 和 SQLite，而不是采信清理程序的 `success: true`。

```bash
python3 /absolute/path/to/app-cleanup/scripts/verify_cleanup.py capture --manifest /absolute/path/manifest.json --output /absolute/path/before.json
# 仅执行当前类别已获准的原生清理；脚本本身不会清理。
python3 /absolute/path/to/app-cleanup/scripts/verify_cleanup.py verify --baseline /absolute/path/before.json --output /absolute/path/after.json
```

移动目标由原生废纸篓 API 实际返回后，按验证契约另传 `--destinations`；不猜废纸篓重名路径。将报告放在目标/保护目录之外，沿用已有任务报告，不另建调度或追踪系统。

## 5. 最小充分操作，然后核对真实结果

使用当前系统的原生卸载、站点数据、凭据或废纸篓接口；优先恢复性操作，但不能悄悄用归档/备份冒充删除。脚本重试前核实已生效范围及原任务，保留原错误。活动数据库先协调停写或取得有效一致性机制，禁止边写边清理。严禁直接复用另一版本、另一机器的删除 SQL。

验证须回答：目标是否按约清除/移动，保留对象是否保持约定不变量，操作是否破坏关联或完整性。清理执行者自报成功、目录大小下降、零搜索结果和关键词消失都不足以单独证明完成。数据库按真实关系清理，事务内核对保留行及外键，提交后再独立只读检查。源码、工作副本、配置及用户指定内容不得因“剩余关键词”继续扩删。

所谓确定验证，只能是**对明确对象、断言、输入版本和观察时点的确定判定**。脚本不是对整台电脑或云端无残留的数学证明，也不能证明存储介质已安全擦除。原生凭据、浏览器云同步、操作系统注册和 UI 状态需要真实原生检查器；不可把人工填的布尔值包装成跨平台验证。没有检查器的项标 `unverifiable`，不报全部通过。不要为了全绿把这些项移出已定清单。

## 6. 交付、接续与结束

每类用简短结果接下一类确认，不重复打印内部路径清单。最终汇总已清理、按选择保留、受阻/未核查、实际恢复入口和必要影响。文件移入废纸篓不等于释放空间；不可恢复凭据删除可能使旧备份无法解密。应用重新打开、活动终端或云同步可重写数据，不能把先前时点的验证说成当前或永久状态。

用户要求结束时立即停止后续盘点/清理，只更新必要任务记录并交付。清理目标之外的任务记录和本 skill 本身不是该应用残留，不为清除字面关键词将其删除。
