# 发现分类定义

每条发现有四个标注：**类型**、**级别**、**置信度**、**建议归属**。

## 类型

| 代码 | 名称 | 定义 | 典型例子 |
| --- | --- | --- | --- |
| **M** | 缺失 Missing | 规则要求的行为在代码中不存在：已找到触发入口，确认没有对应的分支或校验 | 规则要求拒绝，入口却直接执行 |
| **C** | 冲突 Conflict | 代码有对应实现，但结果与规则不同或相反 | 规则取 Effective Version，代码取 latest version |
| **P** | 部分实现 Partial | 只覆盖了部分要素或部分入口 | UI 有校验，API 直调没有；Rule 对了，Denial behavior 不对；单条操作对，批量或导入旁路不对 |
| **X** | 多余 / 无依据 Extra | 本次相关代码中有业务行为经核查适用规范与决策仍无依据，或已撤回的规则仍然生效 | diff 新增的过滤条件在适用的现行规则与决策中都没有依据 |
| **D** | 规范漂移 Drift | OpenSpec 与 Functional Spec 不一致，或缺少对应的 Requirement / Scenario（与代码无关） | Scenario 的 THEN 与 BR 的 Rule 相反；人工核对确认某义务缺少对应 Scenario |
| **T** | 测试缺口 Test gap | BR 没有任何测试覆盖，或测试断言与规则不一致 | 只测了成功路径，没有测 Denial behavior |
| **U** | 无法判定 Unverifiable | 规范含糊、带 `OQ-xxx`，或依赖本次无法访问的系统、仓库，无法得出结论 | 规则引用的外部服务不在 `projects/` 中 |

判定说明：

- 一条发现只标一个类型。同时满足多个类型时，按 **C > M > P > X > D > T** 取第一个，其余写进「差异与影响」。
- 实现没找到但搜索不够充分时，仍然标 **M**，置信度标 **Suspect**。不要另设「疑似」类型。
- **U** 不评级别，级别栏写 `—`。

## 级别

| 级别 | 判定标准 |
| --- | --- |
| **S1 严重** | 违反 INV；或造成越权访问、数据泄露、数据损坏或丢失、合规或审计记录错误；或核心 Rule 结果相反且无规避方法 |
| **S2 高** | BR 的主要 Rule 结果错误或缺失，影响用户可见行为或 API 返回，但范围有限或存在规避方法 |
| **S3 中** | Exceptions、Denial behavior 或边界条件有偏差（错误码、提示文案、次要前置条件）；或 S1 / S2 规则存在 Test gap；或 OpenSpec Drift 会误导实现 |
| **S4 低** | 只影响可追溯性的漂移（如台账、Scenario 措辞）；或其他类型的低影响问题；**改进建议只能放在这一级**，并标注「建议」 |

## 置信度

| 置信度 | 条件 |
| --- | --- |
| **Confirmed** | 具备下表对应类型的完整证据，涉及实现时已追踪完整可达路径，结论不依赖未核实的假设 |
| **Likely** | 已有对应类型的定位证据，但仍依赖一处未完全核实的调用、配置、版本或其他事实，须明确列出 |
| **Suspect** | 没找到实现，或证据不足。必须写明搜索过的关键词和目录 |

### 各类型的必要证据

| 类型 | 证据要求 |
| --- | --- |
| M / C / P | BR / INV 原文要点与位置、固定被审查版本的代码 `file:line`、触发条件及偏离规范的可达路径。未定位入口、仅搜索无结果时不能标 Confirmed |
| X | 固定版本的业务行为与代码位置，以及已核查的适用规范范围和搜索依据；可写「无对应规则」，不强行编造规则 ID。已撤回规则仍生效时引用其 ID 和撤回依据。不能仅因行为不在本次增量规则清单里就判 X |
| D | 相同审查口径下的 FS 原文与 OpenSpec 原文/位置；缺少对应规范时，列出检查过的适用文档、搜索范围和关键词。不要求无关的代码证据；无法访问目标文档时记 U 或盲区，不以未读取当作缺失 |
| T | 按下表核对测试用例及断言，不强求产品代码证据 |
| U | 规则/检查点、无法判定的具体原因及所缺资料或决定，不强求无法获取的代码位置 |

**T（Test gap）的置信度**按以下标准判定：

| 置信度 | T 的条件 |
| --- | --- |
| **Confirmed** | 已核实断言与规则不一致，并给出测试的 `file:line`；或完整检查适用的 test spec、仓库单测、`Freya-Docs-TA` 中的覆盖，写明关键词和范围，均未找到。缺少可访问的来源时不能据此确认无覆盖 |
| **Likely** | 依据台账 `§2` / `§4` 中的 test follow-up 记录，且抽查过至少一处相关用例，确认确实没有覆盖 |
| **Suspect** | 只有台账记录，没有自行搜索或抽查 |

## 建议归属

| 归属 | 何时使用 |
| --- | --- |
| `fix-code` | 规范清楚，代码不符 |
| `fix-openspec` | FS 与代码一致，OpenSpec 落后或写错（多见于 D） |
| `fix-functional-spec` | 代码与 OpenSpec 一致，且有证据（BA 确认、修订历史）表明 FS 自身过时或有误 |
| `needs-decision` | 无法判断哪一方正确，或需要 PM / BA 拍板（多见于 U、X） |
